## 원인

1. 작성자가 주석·인용 제외라는 요구를 구현하면서 정상 MDX, 미종결 inline 문자, JS template의 판정표를 먼저 고정하지 않았다. 반례마다 구현의 해석 범위가 늘었다.
2. 동일 문맥을 prefix 재검색, 열린 JSX 추정, 식별자 추정, 미종결 span 재개 함수가 독립적으로 계산했다. 주석 안 태그를 가리는 수정이 본문 URL을 가렸고, URL을 살리는 수정이 `export default` 주석을 노출했다. 개별 조건 수정으로 해결할 수 없는 상태 소유권의 중복이었다.
3. 리뷰어의 확장 반례가 저장소 밖 임시 스크립트에 남았다. 작성자는 최소 반례를 추가하고 기존 unittest 성공을 확인한 뒤 재리뷰에 들어갔지만, 같은 오류 유형의 문맥 변형은 리뷰 단계에서 처음 실행됐다. 실제 MDX 파서를 실행하지 않고 CommonMark 대조를 MDX 해석의 간접 근거로 사용했다.
4. 정본 [workflow](../../runbooks/agent-workflow.md)는 `BLOCK/CONDITIONAL/PASS`와 P2/P3의 조건부 연기를 허용한다. 반복 manifest가 `PASS/NO-GO`만 요청해 모든 finding을 같은 반복 종료 조건으로 취급했다. 다만 이번 실제 P1 누락은 연기로 닫을 수 없다.
5. coordinator가 post-36 A 원본 확정 전에 B 요약을 전달했다. A 원본에 공개 사실이 기록돼 있으며 해당 회차를 완전한 결과 비공개 리뷰로 간주하지 않는다. 다음 후보는 원본 확정 전 상대 결과를 공유하지 않는다.

## 구조 수정

본문·JS 표현식·ESM·JSX 태그·JSX 자식·template의 스택을 한 전진 커서가 소유한다. 본문 구간에서는 아포스트로피·slash·제어문 단어로 JS 상태를 열지 않는다. 표현식은 실제 중괄호를 소비해 진입하고, 닫힘을 소비할 때 이전 상태로 돌아간다. 공백이나 빈 문단에서 열린 JS 문맥을 재추정하지 않는다. 기존 fence container 계산·패턴·baseline·Git diff·출력 계약은 유지한다.

`_mask_unclosed_inline_span`, `_mask_mdx_resume_comments`, `_has_open_mdx_expression`, `_has_open_jsx_expression`, `_is_mdx_lexical_code`, `_is_executable_mdx_template`와 그 식별자 추정 경로를 제거했다. 미종결 inline delimiter 뒤를 다른 lexer로 다시 처리하지 않는다. TS/TSX/CSS의 기존 처리기는 별도로 유지한다.

문법별 수용 기준은 상세 task에 두고, 누적 자료와 좌표·CLI 시험을 저장소에 포함했다. 참조 파서는 검증 과정에서만 사용한다. 실제 참조 실행은 ESM을 blockquote에 넣은 변형이 최상위 ESM과 같지 않음을 드러냈다. 해당 변형을 성공으로 세지 않고 올바른 문맥 구분을 구현·시험에 반영했다.

## 후속 검증과 종료 조건

- 작성자는 저장소의 누적 자료·문맥 변형·기존 UX 시험을 먼저 통과시킨다. 같은 원인의 변형은 원본 finding ID에 연결한다.
- 두 reviewer는 같은 불변 후보에서 자신의 finding과 전체 수정의 영향 범위를 독립 검토한다. 변경 없는 전체 검증은 정확한 후보의 CI 증거를 확인해 재사용할 수 있으며, 실행하지 않은 검증을 자신의 실행 결과로 적지 않는다.
- 최종 종료는 상세 task 수용 기준, Windows/WSL 검사, 후보 CI, 두 reviewer의 P0/P1 closure와 최종 판정으로 결정한다. 회차 수나 통과 시험 개수만으로 닫지 않는다.
- reviewer 원본은 보존하고 완료 기록은 workflow의 review closure artifact 절차를 사용한다. 결과 요약 문서 때문에 같은 제품 리뷰를 재귀적으로 시작하지 않는다.

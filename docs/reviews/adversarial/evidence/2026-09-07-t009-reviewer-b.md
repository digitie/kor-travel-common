- 영향: 정상 입력인 모든 PR/main/release run에서도 필수 check-versions가 실패해 T-009 및 이후 릴리스 gate를 닫을 수 없다.
- 권고: 같은 report step에서 source를 먼저 기록하고 그 파일을 검증하거나 source 검증과 report 작성/검증을 한 step에 배치한다. step별 파일 분리를 재현한 회귀와 실제 PR/release CI 성공을 확인한다.

## B-P2-03 — 파일명에 포함된 탐지 대상 값을 진단 출력으로 다시 노출함

- 심각도 **P2**, disposition **OPEN**.
- 위치: [tools/_scan.py](../../../../tools/_scan.py) **187~189행**, 발견 결과의 원본 `name`을 JSON `path`로 그대로 출력하는 부분.
- 근거: 내용의 match 값은 출력하지 않지만 경로 문자열은 신뢰한다. 파일명에는 제공자 key 형식이나 사설 주소가 들어갈 수 있으며 이런 문자열은 현재 `path_name()`에서 허용한다. 본문의 발견이 진단을 생성하는 순간 파일명 속 값이 stdout·CI 로그에 기록된다.
- 직접 재현: 분할 생성한 제공자 access-key 형태를 파일명에 넣고 안전한 본문을 검사하면 exit 0이었다. 같은 파일 본문에 별도의 탐지 대상 할당을 추가하자 exit 1과 함께 파일명 속 key 형태가 stdout에 그대로 포함됐다. 같은 방식으로 파일명과 본문에 분할 생성한 사설 주소를 두고 redaction CLI를 실행해 exit 1·주소 원문 출력도 재현했다. 출력은 `marker_in_output=True/False`만 기록해 원문을 재노출하지 않았다.
- 영향: 검사기가 탐지를 위해 실행될 때 숨겨야 할 값을 새 로그로 확산할 수 있다. 안전한 본문일 때의 파일명 미탐지는 추가 관찰이며, 핵심 결함은 발견 진단의 값 비공개 계약 위반이다.
- 권고: 경로도 정보 비공개 출력 경계에서 처리한다. 탐지 패턴을 포함한 경로는 값 대신 식별용 digest/안전한 placeholder를 출력하거나 원문 없는 입력 오류로 중단한다. 두 CLI에서 민감한 파일명·부모 디렉터리명이 stdout/stderr에 남지 않는 회귀를 추가한다.

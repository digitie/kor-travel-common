## A-P2-03 — dark override를 생략하면 common dark가 적용된다는 설명이 CSS와 다르다

- 위치: `docs/standards/design-tokens.md:104` (TK-7), `docs/architecture/style-delivery.md`의 brand.css 마지막 import 예제.
- 최소 재현: candidate `tokens.css`를 먼저 읽고 이후 `:root { --kt-brand: oklch(47% 0.14 255); }`를 두며 `<html class="dark">`에서 computed style을 읽는다. 앱 `.dark` 재선언은 넣지 않는다.
- 실제 Windows Chromium 결과: `--kt-brand = oklch(47% 0.14 255)`, `color-scheme = dark`. 문서가 약속한 common dark `oklch(76% 0.085 169)`가 아니다. :root와 .dark의 specificity가 같아 뒤의 앱 :root가 이긴다. dark-class.css에는 이를 바꾸는 브랜드 선언이 없다.
- 영향: 앱이 dark 전용 override 없이 common dark 팔레트를 사용한다고 오인해 예상하지 않은 색 조합을 배포하거나 잘못된 대비 입력을 선택한다. 이 fallback 보장은 이번 문구에서 추가됐다.
- 최소 수정/수용: 실제 cascade를 명시하고 common dark를 유지하려면 light override의 선택자/순서를 어떻게 제한하는지 검증 가능한 예를 제시한다. dark 생략의 결과를 무조건 common dark라고 보장하지 않는다. class와 media 경로를 구분하고 해당 예의 computed value를 확인한다.

## A-P2-05 — scoped profile의 변수만 재선언하는 절차가 shadcn alias에 적용되지 않는다

### A-P2-01 — 미래 `updated`로 expiry/review 기준일 이동

- 위치: `tools/openapi_exceptions.py:358-395` (`updated` 파싱과 `today`/`sunset`/`review` 검사)
- 근거: `updated <= today` 검사가 없다. `sunset`은 `updated`보다 빠르지 않고 `today`보다 과거가 아니면 통과하며, `review`는 `updated`부터 6개월 이내만 검사한다.
- 재현: canonical YAML을 `updated: "2099-01-01"`, 모든 `review`를 `2099-06-30`, 기한부 `sunset`을 `2099-12-31`로 바꿔 `load_registry(path, as_of=date(2026, 9, 9))` 실행. `46건`으로 ACCEPT. 동일 입력에 `python -B -X utf8 tools/openapi_exceptions.py --write ...` exit `0`, `--check ...` exit `0`.
- 영향: 등록일이 현재보다 미래여도 정본·검사 gate가 이를 거부하지 않아 review 창과 sunset 기준을 미래로 이동시킬 수 있다. 만료·감사 이력이 날짜 문자열 조작에 취약하다.
- 권고: registry `updated`는 검사 기준일보다 미래일 수 없게 fail-closed하거나, 명시된 기준일/커밋 날짜 provenance를 요구한다. 미래 updated·sunset·review 조합을 회귀 시험으로 고정한다.
- disposition: `OPEN` (P2)

### A-P2-02 — 생성 Markdown에 raw HTML/Markdown 구조 주입

- 위치: `tools/openapi_exceptions.py:399-402, 423-430` (`_markdown_cell`, table row 생성)
- 근거: `|`, CR, LF만 처리하고 `<`, `>`, `&`, HTML/Markdown 구문은 escape하지 않는다. `surface`, `reason`, `owner`는 임의의 비공백 문자열을 허용한다.
- 재현: 첫 `reason`을 YAML single scalar `'</td></tr><tr><td>pwn'`으로 교체. `--write` exit `0`, `--check` exit `0`; 생성 파일에 해당 raw fragment가 그대로 남고 Markdown table을 조각낸다. `<img src=x onerror=...>`·외부 링크도 raw output으로 통과한다.
- 영향: 정본 YAML에 들어온 한 문자열이 사람이 검토하는 생성 문서의 table/HTML 구조와 외부 링크·표시를 바꿀 수 있다. 생성 문서의 감사 가독성과 자동 Markdown 소비 안전성이 입력 작성자의 의도에 의존한다.
- 권고: table cell은 plain text로 렌더링하도록 HTML 특수문자와 Markdown 제어 구문을 안전하게 escape하고, 허용할 링크가 있으면 URL scheme/host를 명시적으로 allowlist한다. raw HTML/Markdown 주입 회귀 시험을 추가한다.
- disposition: `OPEN` (P2)

### A-P2-03 — escaped control/surrogate가 parser를 통과하고 출력 gate를 오염

- 위치: `tools/openapi_exceptions.py:86-100`(raw NUL 검사), `147-156`(`json.loads`), `399-402`(출력)
- 근거: raw `\x00`은 거부하지만 double-quoted `\u0000`, `\u0007`, `\u007f`는 decode 후 재검사하지 않는다. lone surrogate `\ud800`도 string으로 수용한다.
- 재현: 첫 `reason`을 `"bad\\u0000value"`로 바꾸면 `--write` exit `0`, `--check` exit `0`, 생성 Markdown에 NUL byte가 포함된다(실행 결과 NUL offset `567`). `"bad\\ud800value"`는 `load_registry`까지 ACCEPT하지만 `--write` exit `2`를 내고 기존 output 파일을 빈 파일(크기 `0`)으로 만든다.
- 영향: 제어문자가 포함된 생성물이 정상 gate로 분류되어 downstream Markdown/도구를 오염시킬 수 있다. surrogate 입력은 실패를 보고하더라도 비원자 write 때문에 기존 생성물을 먼저 손상시킨다.
- 권고: decode 직후 모든 scalar에 허용 Unicode 범위(최소 surrogate·C0 제어·DEL 거부)를 적용하고, 생성은 임시 파일에 완전히 쓴 뒤 `replace`하는 원자적 방식으로 바꾼다. NUL/control/surrogate와 실패 시 기존 output 보존을 회귀 시험한다.
- disposition: `OPEN` (P2)

### A-P2-04 — `--write` input/output alias가 canonical YAML을 파괴

- 위치: `tools/openapi_exceptions.py:451-455` (`generate`의 `write_text`), CLI 인자 정의 `466-474`
- 근거: input/output이 같은 파일인지 `resolve()`·inode·symlink로 확인하지 않고 output을 직접 연다.
- 재현: canonical YAML 복사본 `same.yaml`에 `python -B -X utf8 tools/openapi_exceptions.py --write --input same.yaml --output same.yaml` 실행. exit `0`이지만 파일이 YAML 대신 생성 Markdown으로 대체된다. output symlink가 input을 가리키는 경우도 exit `0`으로 target을 덮는다.
- 영향: 흔한 인자 오타 또는 symlink alias만으로 정본 입력을 파괴한다. 기본 경로는 분리되어도 재사용 CLI의 안전 경계가 없다.
- 권고: resolved input/output가 동일하거나 output이 input으로 연결되면 exit `2`로 거부하고, 출력은 임시 파일+atomic replace로 작성한다. alias·hardlink/symlink fixture를 추가한다.
- disposition: `OPEN` (P2)

### A-P3-01 — 유효한 YAML single-quote escape를 잘못 거부

- 위치: `tools/openapi_exceptions.py:64-79, 103-125, 178-182`
- 근거: doubled single quote(`''`)를 만났을 때 `escaped=True`를 기록하지만 single-quote 상태에서 그 값을 사용하지 않는다. 따라서 유효한 `reason: 'a''b'`가 quote 종료 오류로 거부된다.
- 재현: 첫 reason을 `reason: 'a''b'`로 교체해 `--check` 실행. exit `2`, `single-quote escape 오류`; 직접 parser도 `RegistryError`를 낸다.
- 영향: parser가 구현한다고 보이는 single-quoted scalar의 유효한 YAML subset을 수용하지 못해 정상적인 registry 편집을 불필요하게 막는다. 보안 우회는 아니며 P3으로 분류한다.
- 권고: quote scanner를 YAML single-quote 규칙(`''`는 하나의 문자)으로 통일하거나 single quote를 명시적으로 지원하지 않는다면 문서·코드에서 제거하고 시험으로 고정한다.
- disposition: `OPEN` (P3)

### A-P1-01 — 전이 로컬 링크를 버려 검사 범위 전체가 정상처럼 끝남

- 심각도: P1. 상태: OPEN.
- 위치: [check_versions.py](../../../../tools/check_versions.py) 710–719행, 특히 714–715행의 `entry.get("link")` 즉시 제외.
- 계약: versions §3.2는 명시한 멤버/lock 범위에서도 공유 lock 전체를 대조한다고 정한다. §8은 미지원 로컬 링크를 `NO_LOCK`으로 보고한다고 정한다.
- 재현: root는 `wrapper=file:packages/wrapper`; wrapper는 `react=file:../react`; 로컬 react는 `18.3.1`. npm 11.12.1이 생성한 실제 v3 lock에는 `node_modules/react: {resolved:"packages/react",link:true}`와 `packages/react: {version:"18.3.1"}`가 들어간다. consumer manifest의 `lockfiles=[{kind:"npm",path:"package-lock.json"}]`로 검사하면 **node OK 1개, failing 0, fail 모드 exit 0**이다. root 전체 자동 탐색은 wrapper manifest까지 읽어 NO_LOCK/exit 1이므로 명시 입력과 결과도 달라진다.
- 추가 재현: 합성 lock의 전이 `react` 링크 및 npm blocked 목록에 등록한 `bad` 링크 둘 다 판정 행 없이 누락됐다.
- 영향: 로컬 링크가 축 또는 차단 목록에 해당해도 미확인 상태가 숨겨지고, 후속 CI 표준 호출인 manifest 경로에서 정상으로 집계될 수 있다.
- 권고: 링크의 정책상 패키지 정체성을 확인하고 최소한 해당 축/차단 대상에 `NO_LOCK`을 남긴다. 필요한 경우 lock 안의 link target 메타데이터를 안전하게 대조한다. link target을 실제 지원하지 않으면서 행을 없애면 안 된다. root manifest 단독 호출 회귀를 추가한다.

## 외부 형식 근거와 미검증

2026-09-07 조회한 [npm package-lock 문서](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/)(표시 버전 11.19.1)는 링크 대상이 lock에 함께 들어가며 git resolved가 SHA를 포함하는 형태를 설명한다. [node-semver 고정 README](https://github.com/npm/node-semver/blob/6e05b7637396ac66522cff8731f07cfe0ef49a29/README.md)는 부분 버전과 build metadata의 문법 근거다. 보고서의 구체적 수치 비교는 위 로컬 npm semver 실행으로도 확인했다.

- 소비자 제품 build·npm ci·uv sync·e2e·배포: NOT_RUN(이번 범위 밖). report exit를 제품 gate로 바꾸지 않았다.
- geo Git 원본 재현: NOT_RUN(지정 로컬 저장소 부재). 원본 Git object가 있는 환경에서 추가 재현 가능하다.
- 실제 npm 생성 링크 fixture의 WSL npm 실행: NOT_RUN. Windows npm이 만든 형식과 독립 합성 lock의 Python 검사는 구분했다. 합성 입력 14개는 두 OS에서 실제 실행했다.
- uv/Poetry/requirements 파서의 새로운 의미 검증, T-009 CI 전체 하드닝, 전체 SemVer 구현: 범위 밖. 기존 회귀 suite는 실행했다.
- 원격 CI 결과·PR metadata는 이번 reviewer가 직접 재조회하지 않았다. 로컬 후보 검증과 구분한다.
- 원본 보고서만 추가한다. P1은 수정 또는 근거 있는 반증 후 새 immutable 후보에서 재검토해야 한다.

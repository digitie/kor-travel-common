### A-T011-P1-01 — npm workspace 선택자가 앱의 package.json을 선택하지 않는다

- 위치: `tools/check_versions.py:1813`~1817, `:1939`~1945; `templates/manifests/map.lock.json:8`, `templates/manifests/pinvi.apps-web.lock.json:8`.
- 재현: 저장소 루트 package.json은 workspaces `apps/*`, engines.node `>=22.12.0`; `apps/web/package.json`은 engines.node `>=18.0.0`, dependencies.react `latest`; root v3 lock에는 `apps/web` 선언 및 react 19.2.8 설치본을 넣는다. v1 manifest lock은 `{kind:npm,path:package-lock.json,scope:apps/web}`로 두고 root+manifest CLI를 실행한다.
- 실제: `apps/web node OK`, `react OK`만 반환한다. manifest 없이 같은 root 자동 탐색은 앱의 `node BELOW_FLOOR`와 `react FLOATING_REF`를 반환한다. Windows/WSL 동일하다. report 모드에서는 두 명령 모두 exit 0이므로 exit code가 아니라 실제 누락된 판정으로 확인했다.
- 원인/영향: scope.workspace만 바뀌고 manifest는 계속 lock 옆 루트 package.json이다. 또 해당 workspace를 이미 읽은 manifest로 등록해 lock의 멤버 선언도 건너뛴다. 실제 앱의 런타임·직접 의존성 위반이 정상 값으로 가려진다. 두 초안의 scope `root` 역시 task의 workspace selector 목적과 맞지 않는다.
- 권고: workspace 선택 시 해당 멤버 package.json을 경계 검사 후 읽고 루트 fallback과 구분한다. map/pinvi web 초안에 실제 workspace selector를 넣으며, 명시 scope 및 초안 그대로의 보고 행을 자동 탐색과 대조하는 회귀를 추가한다.

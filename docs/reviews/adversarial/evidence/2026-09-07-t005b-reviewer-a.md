## Findings

### A-P1-01 — equals 형태의 requirement include를 무시한다

- 심각도 **P1**, disposition **OPEN**.
- 위치: `tools/check_versions.py:522`의 long option 분기와 534행.
- 최소 재현: 루트 `requirements.txt`는 `--requirement=child.txt`, child는 `mcp>=2` 한 줄이다. 양 OS에서 report exit 0, `BLOCKED=0`, mcp 행 자체가 없다. 같은 입력을 `--requirement child.txt` 또는 `-r child.txt`로 바꾸면 `BLOCKED=1`이다. `--requirement=missing.txt`도 입력 오류 2 대신 report exit 0으로 끝난다.
- 원인: `=`를 제거한 뒤 다음 글자가 공백인지 다시 요구하므로 정상 파일명이 include에 배정되지 않고 옵션 무시 분기로 빠진다.
- 영향: 표준 재귀 입력의 전체 하위 선언·차단·git 검사를 누락하고 누락 파일 검사도 우회한다.
- 권고: long option의 공백·equals 형식을 함께 파싱하고 반드시 동일한 재귀·존재·순환 검사를 거치게 한다.
- 독립 대조: Windows pip 26.0.1의 `parse_requirements`로 같은 임시 파일을 네트워크·설치 없이 읽어 mcp 선언 1개가 확장됨을 확인했다. 공식 [pip requirements 형식](https://pip.pypa.io/en/stable/reference/requirements-file-format/#referring-to-other-requirements-files), 조회 2026-09-07.

### A-P1-02 — 범위 근사가 차단 구간을 놓치고 동등한 선언도 다르게 판정한다

- 심각도 **P1**, disposition **OPEN**.
- 위치: `tools/check_versions.py:549`~612의 `_range_interval`·`ranges_overlap`.
- 누락 최소 재현: 임시 registry의 기존 mcp 차단 범위만 `>=2.1`로 바꾸고 requirements에 `mcp==2.*`를 둔다. 실제 2.1이 겹치지만 양 OS `BLOCKED=0`이다. wildcard를 제거한 2를 정확 한 점으로 취급하기 때문이다.
- 오탐 대조: 원래 차단 `>=2`에서 `mcp~=1.0`, `mcp < 2`, `mcp<=2,<2`는 각각 `BLOCKED=1`이다. 동등한 `mcp<2,<=2`는 `BLOCKED=0`이다. compatible 상한을 누락하고, 연산자 뒤 공백을 별도 토큰으로 나누며, 같은 상한의 엄격함을 합치지 않는다.
- 영향: 차단 대상 누락과 안전한 범위의 오탐이 모두 발생한다. 해석 불가를 보수적으로 닫는다는 주석으로 wildcard의 false negative는 설명되지 않는다.
- 권고: 지원 범위 문법을 명시하고 wildcard·compatible 상한·연산자 공백·교집합 포함 여부를 정확히 계산한다. 미지원 형태는 무조건 안전한 범위로 축소하지 않는다.
- 독립 대조: pip 26.0.1에 포함된 `SpecifierSet`으로 4개 대표 경계를 확인했다. [PyPA 버전 범위](https://packaging.python.org/en/latest/specifications/version-specifiers/#version-specifiers)는 쉼표 교집합, 연산자 공백, compatible 상한과 wildcard prefix를 정의한다. 조회 2026-09-07.

### A-P2-04 — URL 파싱 예외가 합성 비밀 원문을 annotation으로 내보낸다

- 심각도 **P2**, disposition **OPEN**.
- 위치: `tools/check_versions.py:475`의 검증되지 않은 Poetry URL 전달, `ref_is_pinned`의 URL 분해, 1578행의 원 예외 출력.
- 최소 재현: `marker = "AK" + "IA" + "A" * 16`으로 표식을 만들고 URL hostname을 `"https://[" + marker + "]/repo"`로 구성한다. Poetry git source 또는 requirements의 git URL에 넣는다.
- 실제: 양 OS 두 경로 모두 exit 2이지만 캡처한 stdout/stderr의 `marker in output`이 **true**다. traceback은 없지만 표준 URL 파서의 예외가 입력 hostname을 포함하고 CLI가 그대로 annotation에 삽입한다. 원문은 이 evidence와 도구 출력에 싣지 않았다.
- 영향: 잘못된 파일을 검사하는 것만으로 입력의 민감 문자열이 CI annotation/log에 복제된다.
- 권고: URL 파싱·파일 처리의 외부 입력 예외를 파서 경계에서 일반 오류로 바꾸고 CLI에서도 원 예외를 무조건 출력하지 않는다. JSON·Markdown·annotation·stderr의 비공개 회귀를 함께 둔다.

### A-P2-05 — 미지원 옵션과 잘못된 PEP 508을 정상 선언 입력처럼 통과시킨다

- 심각도 **P2**, disposition **OPEN**.
- 위치: `tools/check_versions.py:533`~538 및 785행의 `parse_requirement`.
- 최소 재현: `--not-a-pip-option whatever`, `fastapi this is invalid`, `custom-lib @`가 각각 report exit 0이다. 첫 사례와 빈 URL은 dependency 행조차 없고 일반 NO_LOCK만 남는다.
- 실제 누락: `-e git+https://github.com/example/custom-lib@main#egg=custom-lib`도 report exit 0이며 `FLOATING_REF=0`이다. 옵션으로 시작한다는 이유만으로 선언을 버린다.
- 영향: 형식 오류를 exit 2로 닫는 정본 계약을 어기고 지원 범위 밖 입력의 미검증 상태를 드러내지 않는다. editable dependency의 이동 ref도 보고에서 사라진다.
- 권고: 허용하는 전역 옵션만 명시적으로 제외하고 의존성을 나타내는 옵션은 해석하거나 입력 오류로 닫는다. PEP 508의 이름 뒤 문법·URL 공란을 검증하고 단순 이름 정규식 일치만으로 입력의 유효성을 인정하지 않는다. 공식 [pip 구조·지원 옵션](https://pip.pypa.io/en/stable/reference/requirements-file-format/#structure), 조회 2026-09-07.

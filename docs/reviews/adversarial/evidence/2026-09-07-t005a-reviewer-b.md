## B-P1-01 — 고정 선언이 lock의 전체 SHA 검증과 복수 Git 항목을 가린다

- 심각도: P1. Disposition: OPEN.
- 위치: `tools/check_versions.py:975`의 마지막 `resolved` 선택, `:977`의 선언별 `record_ref`, `:987`의 `name in urls` 제외. 근본 판정은 `:721`의 선언 또는 전이 양자택일이다.
- 계약: T-005a 구현 범위 2는 lock `source.git`의 전체 SHA fragment를 별도로 확인한다. 버전 정본 §3.2는 marker별 복수 package 보고를, §3.8은 버전형 태그 사용 시 lock의 SHA 기록을 요구한다.
- 재현: 임시 `pyproject.toml`에 `custom-lib` 의존성과 `tool.uv.sources.custom-lib = { git = "https://github.com/example/custom-lib.git", tag = "v1.2.3" }`를 둔다. 유효한 uv v1/revision 3 lock에 해당 package의 `source.git`을 같은 URL의 `?tag=v1.2.3`으로 기록한다. `--mode fail`로 실행하면 custom-lib가 installed `-`, `OK`이고 exit 0이며 error annotation도 없다. fragment에 7자리 SHA를 넣어도 같다. 전체 40자리 SHA를 넣은 양성 대조 역시 OK다.
- 복수 marker 재현: 같은 이름의 1.0.0/2.0.0 Git package를 서로 다른 platform marker로 두고 한 source에만 전체 SHA를 기록했다. 잘못된 항목이 앞이든 뒤든 exit 0·Git OK 한 행이다. 순서를 뒤집으면 보고된 installed가 SHA 접두에서 `-`로 바뀐다. 실제 각 lock 항목을 검사한 결과가 아니다.
- 음성 대조: 같은 SHA 없는 Git lock 항목을 직접 선언 없이 전이로만 두면 FLOATING_REF·error annotation·exit 1이다. 선언이 추가되는 것만으로 동일한 잘못된 lock이 검사를 우회한다.
- 영향: 손상되거나 일부 marker만 미고정된 lock이 필수 fail 모드를 통과한다. 정상 fixture 통과와 기존 139 tests가 이 계약을 보장하지 못한다.
- 권고: 선언의 고정 여부와 모든 lock Git 항목의 전체 SHA 판정을 독립적으로 수행한다. 직접 선언 여부를 이유로 lock 검사를 제외하지 않는다. marker별 서로 다른 참조와 순서를 바꾼 경우, 누락/짧은 SHA에 대한 회귀 시험을 추가한다. 실제 sync 결과를 흉내 낼 필요는 없다.

- 위치: 세 reusable workflow, `consumer-smoke.yml`의 common-ref 검사·checkout.
- 후보 정규식은 40자 SHA 또는 일반 문자열을 허용하고 `main`·`master`만 거부하여 `develop`, `dev`, `stable`, `feature`가 통과한다.
- 이동 branch가 다른 common tool·registry를 실행하게 되어 동일 호출 commit이 재현되지 않는다.
- 40자 소문자 commit SHA 또는 불변 release tag만 허용하고 checkout 후 HEAD를 기록·검증해야 한다.

### B-P1-02 — asset URL이 선택한 pin repository에 결속되지 않음

- 위치: `tools/consumer_smoke.py`의 `validate_asset_url`와 workflow 호출부.
- `digitie/<임의 저장소>/releases/download/.../*.tgz` 형식만 검사하고 selected pin URL과 비교하지 않는다.
- map pin에 다른 저장소 release를 주어도 package name과 digest가 맞으면 승인된다.
- selected pin의 owner/repository와 asset URL을 정확히 비교해야 한다.

### B-P1-03 — 후보 tarball의 GPL license를 확인하지 않음

- 위치: `tools/consumer_smoke.py`의 `validate_asset`.
- `package/package.json`의 name만 비교하여 `license: MIT` 자산도 승인된다.
- registry의 approval license 문자열만으로는 후보 artifact의 GPL 계약을 보장하지 못한다.
- package metadata의 정확한 `GPL-3.0-or-later`, LICENSE/NOTICE, repository provenance를 검사해야 한다.

### B-P2-04 — tar archive의 link/special member를 안전하다고 판정함

- 위치: `tools/consumer_smoke.py` archive 검사.
- symlink·hardlink·device/FIFO, duplicate metadata, member 수와 압축 해제 크기를 제한하지 않는다.
- 후속 extractor 구현에 따라 외부 경로 또는 특수 파일 경계가 열릴 수 있다.
- directory와 regular file만 허용하고 path·duplicate·member·size를 제한해야 한다.

### B-P2-05 — consumer smoke의 Node/npm과 후보 dependency가 고정되지 않음

- runner 이미지와 registry 상태에 따라 smoke 결과가 달라진다.
- SHA 고정 setup-node와 exact Node/npm, `--ignore-scripts --engine-strict --no-audit --no-fund`를 사용해야 한다.

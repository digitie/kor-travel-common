## B-P1-02 — workflow symlink가 입력 root와 local containment를 우회한다

- 심각도: **P1**. Disposition: **OPEN**.
- 위치: `tools/check_versions.py:1598`의 discover_workflows, `:1922`~`:1932`의 resolve 후 repository_root 재계산.
- 재현: 임시 디렉터리에 서로 다른 root와 outside를 만든다. outside/.github/workflows/ci.yml에는 `uses: ./.github/actions/local`을 두고 실제 local 디렉터리는 outside에만 만든다. 아래 두 구성을 각각 실행한다.


- 실제 결과: Windows와 WSL 모두 두 구성에서 `uses local OK` 한 행·fail exit 0이다. 호출한 root/.github/actions/local은 존재하지 않았다.

- 권고: 발견 시 .github/workflows 디렉터리와 각 파일의 resolve 결과가 원래 입력 root 안에 있는지 읽기 전에 검증한다. Scope에 원래 root를 보존하고 local 경로도 그 root를 기준으로 제한한다. 내부 symlink 허용 여부와 외부 symlink 오류를 분리해 두 OS에서 검증한다.

## B-P2-04 — 잘못된 remote/Docker target을 고정 참조 OK로 오분류한다

- 심각도: **P2**. Disposition: **OPEN**.
- 위치: `tools/check_versions.py:1934`~`:1957`의 Docker·remote 분류.

- 실제 결과: 양 OS에서 세 사례 모두 uses OK·fail exit 0이다. 정상 owner/repo SHA/tag, 정상 Docker 이름+버전 tag·digest 대조도 0이므로 target의 구조 차이를 구분하지 못한다.
- 원인: remote target 정규식이 owner/path의 .·.. 성분까지 허용하고, Docker tag 분기는 이미지 이름이 비어 있어도 suffix만 검사한다. digest 분기도 마지막 @ 앞의 값이 비어 있지 않으면 중복 @가 포함된 잘못된 name을 허용한다.
- 영향: task가 미확인으로 남겨야 하는 지원 밖 참조 형태가 정상 고정으로 보고된다. 실제 원격 실행·이미지 내용 확인 없이도 판정할 수 있는 기초 target 구조가 누락됐다.
- 근거: [GitHub workflow uses 문법](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepsuses)과 [Docker image reference 설명](https://docs.docker.com/reference/cli/docker/image/tag/)을 2026-09-07에 확인했다. Docker repository 이름은 필수이며 tag만으로 image를 나타내지 않는다.
- 권고: ref 고정 여부 이전에 지원하는 remote target과 Docker 이름의 기본 문법을 검증한다. 빈 이름·중복 구분자·경로 이동 성분은 정상 OK로 만들지 않고 안전한 미지원 진단으로 남긴다. 원격 조회나 전체 Docker 이미지 해석기를 도입할 필요는 없다.

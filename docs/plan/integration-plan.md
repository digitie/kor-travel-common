# kor-travel-common 통합 실행 계획

이 문서는 단계별 순서·출구·중단 조건을 정의한다. 실행 상태와 선행 관계는 [task 원장](../tasks.md), 개별 수용 기준은 상세 task, 현재 다음 한 작업은 [resume](../resume.md)이 정본이다. 설계는 [architecture](../architecture/README.md), 결정 근거는 [브리프](design-brief.md)와 [ADR 색인](../adr/README.md)을 따른다. 마지막 갱신: 2026-09-07, T-015.

## 1. 현재 실행 범위

사용자는 common 라이브러리와 규칙·도구의 구현을 순차 완주하도록 요청했으며 다른 저장소의 변경과 npm/PyPI 게시를 제외했다. 부트스트랩 문서가 끝난 것은 패키지 구현·소비자 채택·릴리스 완료가 아니다. 패키지 실물과 실행 상태는 resume·task 원장에서 확인한다.

조사의 테스트 개수·버전·소비자 상태는 고정 커밋 관찰이다. 최신이라고 재인용할 때는 원천과 조회일을 확인한다. common의 로컬 fixture 결과·소비자의 실제 실행·미실행을 구분한다. 이름 확보와 공개 게시 계획 철회, 검증 후보 보존 후 다음 구현 순서는 [ADR-014](../adr/014-common-implementation-without-registry-publishing.md)를 따른다.

## 2. 한 에이전트가 한 작업씩 실행하는 규칙

1. AGENTS → 문서 지도 → resume → 지정한 상세 task 하나를 읽는다.
2. 진행 중 task의 선행이 충족되면 먼저 마무리한다. 한 번에 하나만 IN_PROGRESS로 둔다.
3. 원장의 대기열에서 내부 선행이 모두 DONE이고 외부 조건이 충족된 common 작업 하나를 선택한다. 기반 → 토큰 → UI → Python → 공통 운영/도구 분류 안에서 P0~P3, 동순위 ID 순이다. 소비자 저장소 변경·실행 task는 현재 범위에서 선택하지 않는다.
4. 외부·미래 시점의 대기는 BLOCKED에 이유·담당·필요 evidence를 명시하고 독립적인 다음 common 작업으로 넘어간다. 시간 경과나 사용자 기본값을 승인으로 보지 않는다.
5. 한 task의 구현·검증·두 독립 리뷰·수정·재검토를 수행한다. 소스와 규범 변경은 같은 immutable 후보에서 검토한다. gate가 남으면 완료하지 않는다.
6. 완료 원장·상세 evidence·resume을 동기화하고 커밋·push·draft PR을 갱신한다. 필수 리뷰·CI가 통과하면 PR을 병합하고 다음 task로 넘어간다. main 직접 push는 금지다.

여러 단계가 섞인 task는 실행 전 하위 task로 나눈다. common fixture 성공만으로 외부 검증이 필요한 부모를 DONE으로 만들지 않는다. 번호·Phase는 분류이며 task DAG와 외부 선행이 실행 가능성을 결정한다.

## 4. rc 검증과 정식 채택

T-109a·T-212a·T-213a·T-310a는 common 후보 보존이며 정식 릴리스가 아니다. T-010은 실행기와 fixture, T-010a는 승인된 실제 소비자 2곳 dispatch를 소유한다. 릴리스 task(T-109·T-212·T-213·T-310·T-311)는 보존 후보에서 rc를 준비하고 외부 검증을 요청한다. 소비자 담당자가 별도 PR에서 설치·검증해 결과를 돌려준다.

rc 검증에 해당 버전의 정식 채택 task DONE을 선행으로 요구하지 않는다. 정식 채택은 정식 자산 URL·lock으로 갱신한 후 최종 재검증·merge한다. 이전 minor 채택 조건은 유지한다. UI 0.2 외부 검증은 map T-411과 선택한 두 번째 소비자 T-422a 또는 T-432의 0.1 채택 이후다. pinvi는 T-020 → T-420 → T-421 → T-422a → T-422b → T-422 순서를 유지한다.

common 에이전트는 소비자 저장소를 수정하지 않는다. 외부 대기 중 릴리스 task는 BLOCKED로 두고 다음 common 구현을 선택한다. 보존 후보에서 분기한 release branch를 사용해 main의 다음 minor 코드를 과거 버전으로 발행하지 않는다. UI 0.2 common 후보 보존은 T-213a, Python 0.2 후보 보존은 T-311의 준비 범위이며, UI 외부 rc·정식은 T-213이 T-213a 후보에서 이어간다. release branch의 task 원장은 과거 스냅샷으로 유지하고, 현재 선행 확인·완료와 후속 READY 갱신은 [release §2.2](../runbooks/release.md#22-릴리스-소스와-현재-작업-원장의-연결)의 main 문서 PR을 따른다. 선택 소비자·peer 계약은 ADR-013의 유지 조항, 구현/발행 분리는 ADR-014를 따른다.

## 5. 외부 결정과 인계

열린 결정은 [브리프 §2](design-brief.md#2-사용자-확인이-필요한-열린-결정기본값으로-진행)에서 추적한다. O-5는 ADR-014로 닫았으며 npm/PyPI 소유권 확인을 완료한 뜻이 아니다. 권리(L6/L8), 명시 예외(O-8), 타 저장소 현재 상태·React 승인은 담당 evidence 없이 해제하지 않는다.

인계에는 현재 commit·PR, 검증 결과, 실패/NOT_RUN과 영향받는 gate, 다음 task·시작 파일, 외부 결정 해제 조건을 남긴다. 모든 common 코드를 구현해도 외부 릴리스/채택이 BLOCKED라면 제품 출시 완료로 보고하지 않는다.
